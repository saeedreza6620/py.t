# راهنمای این بسته: ادامه پروژه GRM با Gemini

**تاریخ:** ۲۱ آبان ۱۴۰۵ (۱۲ نوامبر ۲۰۲۶)
**پروژه:** مدل ریاضی رهایش دارو از میکروسفر ژلاتین کراس‌لینک‌شده با گلوتارآلدئید (GRM نسخه ۱٫۱) و مسیر تبدیل آن به محصول

## ⚡ سریع‌ترین راه: Gemini مدل‌سازی را کامل کند و HTML بدهد

۱. بهترین حالت: در Gemini یک **Gem** بسازید (مثلاً «GRM مدلسازی»).
   - در بخش Knowledge، فایل `GEMINI_KNOWLEDGE_BASE.md` را آپلود کنید.
   - در Instructions این را بنویسید: «فارسی و ساده جواب بده. هیچ پارامتری روی منحنی آزمون برازش نشود. هر عدد منبع داشته باشد. قواعد فایل‌های 07 و 12 و ادامه با همین طراحی را رعایت کن.»
   - اگر Gem ندارید، یک گفتگوی تازه کافی است. Google AI Studio هم گزینه خوبی است، چون می‌توانید اجرای کد (Code execution) را روشن کنید.
۲. فایل `GEMINI_KNOWLEDGE_BASE.md` را در گفتگو آپلود کنید (اگر در Gem گذاشته‌اید، لازم نیست).
   - اگر Gemini گزینه وارد کردن کد (Import code) دارد، می‌توانید نشانی گیت‌هاب شاخه یا خود زیپ را هم بدهید.
۳. این جمله را بفرستید:
   «فایل GEMINI_KNOWLEDGE_BASE.md را کامل بخوان. نقش و قواعد بخش 01 و ماموریت بخش 13 را اجرا کن. فعلاً کد ننویس و فقط پاسخ اول خواسته‌شده در بخش 13 را به فارسی بده.»
۴. پاسخ Gemini را با این سه معیار چک کنید:
   - قاعده «هیچ پارامتری روی منحنی آزمون برازش نمی‌شود» را تکرار کرده باشد؛
   - گفته باشد می‌تواند پایتون اجرا کند یا نه؛
   - فهرست مقاله‌هایی را که لازم دارد با DOI داده باشد.
۵. PDF مقاله‌هایی را که خواست آپلود کنید. بعد بنویسید: «M1 را شروع کن». بعد از هر بسته کاری (M1 تا M8) خروجی را بگیرید و اجرا کنید (بخش ۳ پایین).
۶. در پایان، Gemini فایل `GRM_2.0_Model_Report.html` را می‌دهد. این یک فایل HTML آفلاین است با هفت بخش: مدل، منشأ پارامترها، اعتبارسنجی، وزن پارامترها، شبیه‌ساز، طراحی معکوس و محدودیت‌ها.

> **ادامه با همین طراحی:** در دستور Gemini صریحاً نوشته‌ام که ساختار مدل (استخرها، هسته فیک، برچسب منشأ پارامترها)، طراحی اعتبارسنجی (V0 تا V4، W1 و W2 و ادامه شماره‌ها) و ظاهر شبیه‌ساز ۱٫۱ (همان رنگ‌ها، چیدمان و نمودارها) عوض نشود و فقط گسترش پیدا کند.

> **اجرا در Google Colab:** اگر Gemini کد را اجرا نکرد، از او بخواهید «یک سلول Colab بده که شاخه را clone و run_all و تست‌ها را اجرا کند». خروجی را برایش بفرستید.

> **اگر Gemini نتواند پایتون اجرا کند:** کنار هر عدد باید «NOT RUN» بنویسد. شما دستورها را اجرا کنید و خروجی را برایش بفرستید. عددی را که اجرا نشده، نتیجه حساب نکنید.

## ۳. چطور Gemini را راه بیندازید (گام‌به‌گام)

1. یک گفتگوی تازه در Gemini باز کنید (اگر امکان ساخت Project/Workspace دارد، یک Project بسازید).
2. **کل این ZIP را آپلود کنید.** اگر Gemini فایل ZIP نپذیرفت، این فایل‌ها را جدا آپلود کنید: `01`، `02`، `07`، `09`، `10`، `11`، `thesis_docs/markdown/Literature_Review_Gelatin_Microspheres_final.md` و `repo_snapshot/gelatin_release_model/README.md`.
3. متن کامل `01_GEMINI_MASTER_PROMPT.md` را به‌عنوان پیام اول بفرستید.
4. از Gemini بخواهید فقط خلاصه بدهد که چه فهمیده و برنامه‌اش برای کار اول چیست. **قبل از اینکه کد بنویسد، خلاصه را چک کنید:** باید قاعده «هیچ پارامتری روی منحنی آزمون برازش نمی‌شود» را تکرار کند.
5. از `08_TASK_PROMPTS.md` یک کار را بردارید و بفرستید. هر بار فقط یک کار.
6. Gemini نمی‌تواند خودش در گیت‌هاب شما push کند. خروجی را به یکی از این دو شکل بخواهید:
   - فایل‌های کامل تغییرکرده (با مسیر دقیق)، یا
   - یک patch با فرمت `git diff`.
7. تغییر را در کامپیوتر خودتان اعمال و آزمایش کنید:
   ```
   git checkout modeling/gelatin-release-model-v1
   git checkout -b gemini/<نام-کار>
   # فایل‌ها را جایگزین کنید یا:  git apply gemini.patch
   python validation/run_all.py && python -m pytest -q
   git add -A && git commit -m "<توضیح>" && git push -u origin gemini/<نام-کار>
   ```
8. **فقط اگر همه تست‌ها رد شدند و عدد اعتبارسنجی بدون توضیح عوض نشد**، شاخه را ادغام کنید.

## ۴. سه علامت هشدار در کار Gemini

- اگر ضریب نفوذ یا هر پارامتری را روی همان منحنی‌ای برازش کرد که با آن مدل را «تأیید» می‌کند، کار را رد کنید.
- اگر عددی بدون منبع (مقاله، شکل، صفحه) اضافه کرد، منبع بخواهید.
- اگر گفت «همه آزمون‌ها قبول شد» ولی خروجی `run_all.py` را نشان نداد، باور نکنید و خودتان اجرا کنید.

## ۵. خلاصه وضعیت در یک نگاه

- **مدل:** داروی آزاد + متصل ضعیف + متصل به شبکه (آزادشدن با تخریب) + آبگیری؛ خروج با قانون فیک از کره.
- **صحت‌سنجی:** خطای حل عددی ۰٫۰۱ واحد درصد.
- **اعتبارسنجی:**
  - Cheng: دو غلظت GA پیش‌بینی‌شده، خطای ۲٫۴ و ۴٫۰ واحد درصد، قبول.
  - Mladenovska: اثر اندازه ذره، خطای ۳٫۶ تا ۵٫۷، قبول.
  - Chang→Hu: ۹٫۴ بعد از روز اول، قبول ناقص.
  - Saravanan: فیک تنها، شکست مورد انتظار.
- **وزن پارامترها:**
  - تورم تقریباً وزن ندارد.
  - کراس‌لینک از راه اتصال دارو اثر می‌کند.
  - پارامترهای فیک فقط وقتی نفوذ کند است مهم‌اند (عدد Λ).
  - تخریب انتهای منحنی را کنترل می‌کند.
- **کارهای باز:**
  - وابستگی جداشدن دارو به نمک محیط؛
  - توزیع اندازه ذره؛
  - رابطه تخریب با درجه کراس‌لینک؛
  - لایه یادگیری ماشین؛
  - گسترش به PLGA.
