# اپ اندروید بیوتی‌ولت (و راه آیفون)

> از نسخه‌ی ۱۴۴ (۲۱ آبان ۱۴۰۵). برای صاحب پروژه و هر هوش مصنوعی یا برنامه‌نویسی که ادامه می‌دهد.
> اسم بسته: **`ir.beautywallet.app`**. این اسم بعد از انتشار در بازار **هرگز** نباید عوض شود.

## ۱. اپ اندروید چیست

- یک اپ اندرویدی واقعی است که با Capacitor 7 ساخته شده و **همان سایت زنده** (`https://beautywallet.liara.run/legacy/`) را باز می‌کند. هر به‌روزرسانی سایت، بدون انتشار دوباره‌ی APK، در اپ هم دیده می‌شود.
- **فرق اصلی با وب‌اپ:** یادآور روتین صبح و شب و پیگیری محصولات **روی خود گوشی** زمان‌بندی می‌شود. پس سر ساعت می‌آید، حتی وقتی گوشی اینترنت ندارد و حتی بعد از خاموش و روشن شدن گوشی.
- داخل اپ دکمه‌ی «افزودن به صفحه‌ی اصلی» پنهان است و push وب استفاده نمی‌شود.

**فایل‌ها:**

| فایل | کار |
| --- | --- |
| `android-app/capacitor.config.json` | اسم بسته، اسم اپ، آدرس سایت، صفحه‌ی بی‌اینترنتی |
| `android-app/www/error.html` | صفحه‌ای که اگر بار اول اینترنت نباشد دیده می‌شود |
| `android-app/assets/` | آیکن و صفحه‌ی شروع (از آیکن‌های سایت) |
| `android-app/patch-android.mjs` | مجوزها، آیکن کوچک اعلان، شماره‌ی نسخه، امضای اپ |
| `claude/native.js` | زمان‌بندی یادآورها روی گوشی + راهنمای نصب آیفون |
| `claude/followup.js` | داخل اپ، روشن کردن یادآور به‌جای push وب از `native.js` استفاده می‌کند (`NAT()`) |
| `.github/workflows/android.yml` | ساخت خودکار APK در گیت‌هاب |

پوشه‌ی `android-app/android/` در مخزن نیست. هر بار در گیت‌هاب از نو ساخته می‌شود.

## ۲. ساخت APK

- **خودکار:** هر push به `main` که `android-app/**` را تغییر بدهد، یا دستی از تب **Actions ← Android APK ← Run workflow**.
- **گرفتن فایل:** در همان صفحه‌ی اجرا، پایین صفحه بخش **Artifacts** ← `BeautyWallet-apk-N`. داخل zip، فایل APK است.
- **دو حالت دارد:**
  - **بدون کلید امضا:** `BeautyWallet-N-debug.apk`. فقط برای تست روی گوشی خودتان مناسب است، نه برای بازار.
  - **با کلید امضا:** `BeautyWallet-N.apk`. برای کافه‌بازار، مایکت و لینک مستقیم.
- **شماره‌ی نسخه (versionCode)** خودکار همان شماره‌ی اجرای گیت‌هاب است، پس هر APK تازه روی قبلی نصب می‌شود. اسم نسخه از `version` در `android-app/package.json` می‌آید.

## ۳. کلید امضا: فقط یک بار، فقط خودت

کلید امضا ثابت می‌کند به‌روزرسانی‌ها از طرف خود شماست. **اگر گم شود، دیگر نمی‌شود اپ را در بازار به‌روز کرد.**
- آن را با رمزهایش در دو جای امن نگه دار.
- **هرگز در چت، ایمیل یا گیت‌هاب نفرست.**

**ساختن کلید** روی کامپیوتر خودت انجام می‌شود و جاوا (JDK) لازم دارد:

```bash
keytool -genkeypair -v -keystore beautywallet.keystore -alias beautywallet -keyalg RSA -keysize 2048 -validity 10000
```

**تبدیل کلید به متن base64:**

```bash
# macOS / Linux
base64 -i beautywallet.keystore | tr -d '\n' > keystore.txt
# Windows PowerShell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("beautywallet.keystore")) | Out-File keystore.txt
```

**گذاشتن در گیت‌هاب:** **Settings ← Secrets and variables ← Actions ← New repository secret**. این چهار مورد را بساز:

| اسم | مقدار |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | محتوای `keystore.txt` |
| `ANDROID_KEYSTORE_PASSWORD` | رمز کلید |
| `ANDROID_KEY_ALIAS` | `beautywallet` |
| `ANDROID_KEY_PASSWORD` | رمز همان alias |

بعد یک بار **Run workflow** بزن تا APK امضاشده ساخته شود.

### راه ساده‌تر: ساختن کلید روی گیت‌هاب، بدون نصب جاوا

1. مخزن را **خصوصی** کن: Settings ← General ← Danger Zone ← Change visibility ← Private.
2. یک رمز قوی انتخاب کن (حداقل ۸ حرف) و **به هیچ‌کس نگو، حتی در چت.** این سه secret را بساز:
   - `ANDROID_KEYSTORE_PASSWORD` = همان رمز
   - `ANDROID_KEY_PASSWORD` = همان رمز
   - `ANDROID_KEY_ALIAS` = `beautywallet`
3. Actions ← **Android signing key (one time)** ← Run workflow. اگر مخزن عمومی باشد یا قبلاً کلید ساخته شده باشد، خودش اجرا نمی‌شود.
4. در صفحه‌ی همان اجرا، از **Artifacts** فایل `beautywallet-signing-key` را دانلود کن.
5. محتوای `ANDROID_KEYSTORE_BASE64.txt` را کامل کپی کن و secret چهارم را بساز: `ANDROID_KEYSTORE_BASE64`.
6. همان zip را با رمزش (جدا از هم) در دو جای امن نگه دار، و بعد artifact را در گیت‌هاب پاک کن.
7. Actions ← **Android APK** ← Run workflow. از این به بعد APK امضاشده (`BeautyWallet-N.apk`) ساخته می‌شود.

## ۴. انتشار

- **کافه‌بازار** (پیشخوان توسعه‌دهندگان) و **مایکت:** با حساب توسعه‌دهنده، APK امضاشده را بارگذاری کن. متن صفحه‌ی اپ، کلیدواژه‌ها و اسکرین‌شات‌ها در `docs/STORE_LISTING.md` آماده است. سیاست حریم خصوصی: `https://beautywallet.liara.run/privacy.html`.
  - توضیح و عکس‌ها از سایت گرفته شود.
  - دسته‌ی پیشنهادی: «سلامت و زیبایی».
- **لینک مستقیم:** همان APK را روی سایت هم می‌شود گذاشت.
- **گوگل‌پلی:** برای توسعه‌دهنده‌ی ایرانی به‌خاطر تحریم فعلاً عملی نیست.

## ۵. داده‌ی کاربران

- داده‌ی داخل اپ از کروم جداست. کاربری که قبلاً از کروم استفاده کرده، در اپ **با همان شماره وارد می‌شود** و روتین، پروفایل و ساعت یادآورش از نسخه‌ی ابری برمی‌گردد (`claude/cloud-sync.js`).
- عکس‌های پوست پشتیبان رمزشده‌ی جدا دارند.
- `native.js` فقط دو کلید **تازه** می‌نویسد:
  - `bw_native_notif`: وضعیت اجازه‌ی اعلان
  - `bw_native_sig`: برای اینکه زمان‌بندی بی‌دلیل تکرار نشود
- به هیچ داده‌ی دیگری دست نمی‌زند.

## ۶. یادآورها روی اندروید

- **روشن کردن:** همان دکمه‌ی «روشنش کن» در کارت یادآور. اجازه‌ی اعلان خواسته می‌شود (اندروید ۱۳ به بعد) و یک اعلان آزمایشی ۴ ثانیه بعد می‌آید.
- **زمان‌بندی:**
  - صبح و شب: هر روز سر ساعت انتخابی کاربر (`schedule.on`).
  - پیگیری محصولات (روز سوم، هفته‌ی ۲ و…): یک‌باره در روز خودش، ۲ دقیقه بعد از یادآور صبح (یا شب).
  - متن‌ها همان متن‌هایی است که برای push وب ساخته می‌شود (`plan` در IndexedDB `bw-followup`).
- **اجازه‌ی «آلارم و یادآور»:** اندروید ۱۲ به بعد برای «دقیقاً سر ساعت» این اجازه را می‌خواهد. اگر نباشد، یک کارت کوچک پیشنهادش را می‌دهد. بدون آن هم یادآور می‌آید، فقط شاید چند دقیقه دیرتر.
- **گوشی‌های شیائومی، سامسونگ و هوآوی:** بهینه‌سازی باتری ممکن است اعلان را عقب بیندازد. در تست حتماً روی یکی از این‌ها امتحان کن. اگر دیر رسید، راهنمای «بهینه‌سازی باتری ← بدون محدودیت» را به کاربر بده.

## ۷. آیفون

- **App Store** برای توسعه‌دهنده‌ی ایرانی عملاً در دسترس نیست.
- **فروشگاه‌های ایرانی آیفون** با گواهی‌هایی کار می‌کنند که اپل گاهی باطل می‌کند.
- **تصمیم:** آیفون فعلاً **همان وب‌اپ نصب‌شده روی صفحه‌ی اصلی** است. از iOS 16.4 به بعد، اگر اپ به صفحه‌ی اصلی اضافه شده باشد، push وب کار می‌کند. یادآور کاملاً آفلاین روی آیفون ممکن نیست.
- **راهنمای نصب:** `native.js` در Safari (وقتی اپ هنوز به صفحه‌ی اصلی اضافه نشده) حداکثر هر ۴ روز یک بار کارت «بیوتی‌ولت رو به صفحه‌ی اصلی آیفونت اضافه کن» را نشان می‌دهد. این کارت راهنمای نصب موجود را باز می‌کند (`install-app.js`).
- اگر روزی راه انتشار آیفون باز شد، همین پروژه‌ی Capacitor با `npx cap add ios` برای آیفون هم ساخته می‌شود، ولی مک و حساب اپل لازم دارد.

## ۸. چک‌لیست تست قبل از انتشار عمومی

روی یک گوشی اندروید واقعی، ترجیحاً شیائومی یا سامسونگ:

1. APK را نصب کن و اپ را باز کن. صفحه‌ی خوش‌آمد باید بدون دیده شدن صفحه‌ی قدیمی بیاید.
2. با شماره‌ی خودت وارد شو. روتین و پروفایلت باید برگردد.
3. یادآور را روشن کن و اجازه بده. اعلان آزمایشی باید بیاید.
4. ساعت یادآور را ۲ دقیقه بعد بگذار، **گوشی را در حالت هواپیما ببر** و صبر کن. یادآور باید بیاید.
5. گوشی را خاموش و روشن کن و دوباره مرحله‌ی ۴ را تکرار کن.
6. اینترنت را قطع کن و اپ را ببند و باز کن. اپ باید از حافظه باز شود.
7. یک خرید الماس کوچک را تا مرحله‌ی «ثبت پرداخت» برو و برگرد.

## ۹. تست بدون گوشی (برای هوش مصنوعی بعدی)

`scripts/e2e/android-native.cjs` یک Capacitor ساختگی در مرورگر می‌سازد و همه‌ی درخواست‌هایی را که اپ به گوشی می‌فرستد ثبت می‌کند:
- اجازه‌ی اعلان
- زمان‌بندی صبح و شب و پیگیری‌ها
- زمان‌بندی دوباره بعد از تغییر ساعت
- پنهان بودن دکمه‌ی نصب

همین تست، راهنمای آیفون و دست نخوردن کروم معمولی را هم بررسی می‌کند. اجرا مثل بقیه‌ی تست‌های `scripts/e2e/README.md` است.

**ساختن APK در محیط Claude ممکن نیست،** چون ابزار اندروید در دسترس نیست. ساخت فقط در GitHub Actions انجام می‌شود.
