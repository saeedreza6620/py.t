## ۳. قوانینی که صاحب پروژه گذاشته (هرگز نشکن)

1. **داده‌ی کاربر از بین نرود:** اسم، روتین، ساعت یادآور، عکس‌ها، تیک‌ها و هر تغییری که داده.
   - فقط کلید تازه اضافه کن.
   - تست `test-keep-user-data` نگهبان این قانون است.
2. **هیچ کلید یا رمزی** نباید در چت، کد یا گیت‌هاب باشد. کلیدها فقط در متغیرهای لیارا یا GitHub Secrets هستند و هرگز از صاحب پروژه کلید نخواه.
   - **شماره کارت را فقط خودش در پنل وارد می‌کند.**
3. **هیچ پیامکی خودکار یا زمان‌بندی‌شده نفرست.** فقط متن و فهرست آماده کن.
4. **صداقت:**
   - وعده‌ی چیزی که ساخته نشده نده.
   - داده، نظر یا لینک ساختگی نساز.
   - فقط وقتی بگو «بررسی انسانی» که آدم واقعی بررسی کند.
   - لحن عاشقانه یا وابستگی‌ساز نداشته باش.
   - آمار زیر ۱۰ نمونه به کاربر نشان نده.
5. **مرز پزشکی:**
   - تشخیص و درمان نده.
   - علامت خطر یعنی ارجاع به پزشک.
   - سؤال‌ها باید بر پایه‌ی منبع علمی باشند.
   - **پیام دارای علامت خطر در دستیار همیشه رایگان است.**
6. **الماس بعد از ارزش:** درست قبل از دیدن نتیجه‌ی قدم بعد خواسته می‌شود، نه فقط در آخر کار. درآمد هرگز روی جواب «بخر یا نخر» اثر ندارد.
7. **فهرست مواد یا عکس پشت جعبه را از کاربر نخواه.** در کاتالوگ هم قیمت نگذار.
8. **دستیار کاربر را جای دیگری نمی‌فرستد** که دنبال جواب بگردد. یک قدم مشخص برای همان لحظه می‌دهد.
9. **قبل از هر انتشار:**
   - ۷ تست نگهبان رد شوند.
   - با Playwright بررسی کن (`scripts/e2e/`).
   - صادقانه بگو چه چیزی روی گوشی واقعی تست نشده: هوش مصنوعی زنده، پیامک، push، پرداخت واقعی، دوربین، آیفون.
10. **کل روند را روی گیت‌هاب با فایل md نگه دار.** بعد از هر نسخه، `README.md` (بخش ۶)، جدول نسخه‌ها در `docs/PROCESS.md` و همین فایل را به‌روز کن.

## ۴. تصمیم‌های راهبردی تا امروز

- **نقطه‌ی ورود:** «پوستم به هم ریخته» (کار حاد، بیشترین تمایل به پرداخت).
  - **دلیل ماندن:** «آیا جواب می‌ده؟»، یعنی صفحه‌ی «امروز»، عکس‌ها و پیگیری.
- **مزیت کپی‌ناپذیر بدون داده‌ی کاربر:**
  - تخصص بنیان‌گذار در مدل‌سازی رهایش دارو، که پشت پرده و برای دقت جواب‌ها به کار می‌رود. **کاربر فقط جواب ساده می‌بیند.**
  - pH اندازه‌گیری‌شده
  - فرمول تأییدشده از نماینده‌ی برندها
  - موقعیت معکوس در برابر فروشگاه‌ها: «ما نمی‌فروشیم، می‌گیم نخر»
- **بخش مشتری مرفه:** «بیوتی‌ولت پرایوت» (مشاور انسانی واقعی، بازبینی قفسه، اصالت، پرونده‌ی پوست). **اول دستی با ۱۰ عضو بنیان‌گذار تست می‌شود** و بعد ساخته می‌شود. هنوز در اپ ساخته نشده.
- **رد یا کنار گذاشته شد:**
  - تزریق (صاحب پروژه نخواست)
  - مکمل‌ها (پنهان شد)
- **ایده‌ی پارک‌شده:** عطر (عطرشناس شخصی و ست دکانت). فقط تست دستی ۱۰ نفره پیشنهاد شده.
- **مدل درآمد فعلی:** الماس.
  - دستیار: ۸ پیام هدیه، بعد ۱ الماس = ۱۰ پیام
  - نتیجه‌ی تست ساعد: ۳ الماس
  - جایگزین‌ها: ۱ الماس
  - بسته‌ها، طبق پیش‌فرض کد: ۵ الماس = ۱۲۵ هزار تومان، ۱۵ الماس = ۳۳۰ هزار تومان. قیمت واقعی همان است که در پنل زنده تنظیم شده.
  - همه از پنل قابل تغییرند.
- **کانال‌های پیدا کردن مشتری پیشنهادشده:**
  1. ۵ کاربر فعال، با پیام دستی «عضو بنیان‌گذار»
  2. نی‌نی‌سایت و کامنت‌های پیج‌های پوستی، با جواب مفید و معرفی شفاف
  3. اینفلوئنسر کوچک
  4. داروخانه
  5. خوابگاه دانشجویی

## ۶. دام‌های فنی که قبلاً به آن‌ها خورده‌ایم

- **پل `claude/claude-bridge.js`** درخواست‌های `fetch('/api/…')` را می‌گیرد.
  - هر API تازه را باید در خط عبور آن اضافه کنی.
  - الگوی مسیرش عدد را نمی‌پذیرد.
- **`saveCfg` در `lite/server.mjs`** تنظیمات را از نو می‌سازد. هر کلید تنظیم تازه را باید **هم آنجا و هم در فرم پنل** (`lite/admin.mjs`) اضافه کنی، وگرنه با اولین ذخیره‌ی پنل پاک می‌شود.
- **فهرست `EVENTS`** در `lite/server.mjs`: رویدادی که آنجا نباشد، ثبت نمی‌شود.
- **کلیدهای ابری** در `lite/cloud.mjs` و `claude/cloud-sync.js` باید **یکسان** باشند.
- **ترتیب لایه‌ها:**
  - صفحه‌ی الماس (`.sw-sheet-back`) در z-index 10060 است، بالای دستیار (10050).
  - پیام‌ها (`.sw-toast`) در 10070 هستند.
- **تب‌ها:**
  - `sw-home`: صفحه‌ی اصلی
  - `sw-routine`: تیک‌های روتین
  - `track`: کارت برنامه‌ی آرام‌سازی و دفترچه‌ی عکس
  - `sw-me`، `sw-gift`
- **تیک روتین** در `bw_track_YYYY-MM-DD` ذخیره می‌شود. روز بر اساس تاریخ تهران است.
- **سایت زنده از محیط Claude در دسترس نیست،** چون پروکسی اجازه نمی‌دهد. همه چیز را روی سرور محلی تست کن.
- **ساختن تگ و نوشتن مستقیم با REST گیت‌هاب** از محیط Claude بسته است. برای پشتیبان شاخه‌ی `backup/...` بساز.
- **صفحه‌ی خوش‌آمد** («امروز اومدی چیکار کنیم؟») هر بار که اپ تازه باز می‌شود می‌آید (`sessionStorage bw_wel_v1`). در تست‌ها اگر آن را رد کنی، صفحه‌ی اول واقعی را نمی‌بینی. یک بار به همین دلیل ارزیابی اشتباه دادیم.

## ۷. شروع سریع برای ادامه

```bash
git clone https://github.com/saeedreza6620/py.t && cd py.t
# change files in claude/ (the app), lite/*.mjs (the server), claude/site/ (the site)
node scripts/apply-sweet-ui.mjs 144 && node scripts/build-lite.mjs   # a NEW version number every time
npm i --no-save typescript@5.9.3
for t in skin-fit catalog-review catalog-routine bank explain catalog-quality keep-user-data; do node scripts/test-$t.mjs || echo "FAIL $t"; done
# browser checks: scripts/e2e/README.md
git add -A && git commit -m "v144: …" && git push origin main      # GitHub Actions deploys to Liara (~2 min)
```

پیام هر commit با `vNNN:` شروع می‌شود و توضیح می‌دهد چه چیزی و چرا تغییر کرد. تاریخچه‌ی کامل در `git log` است.
